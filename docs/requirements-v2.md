# PointLog 需求说明 v2

> 状态：需求确定中（v2 范围）
> v1 已完工并验收（见 `requirements-v1.md`）。本文档在 v1 基础上规划 v2，随开发持续演进。

## 0. v2 背景与目标

**v1 解决**：把每天的投入量化成点数，找回"今天没白过"的正反馈（打卡/感想/备忘录/主目标/点数线/贡献日历/多档案+PIN/导出）。

**v2 想补的两块拼图**：
1. **"看懂自己"**——除了每天记，还要能回顾：我坚持了多久、时间花在哪、在进步还是滑坡（统计仪表盘）。
2. **"看懂钱"**——轻量地知道自己的资产状况，且不违背 PointLog"随性、极轻、私密"的基因（资产 + 随性记账）。

**地基**：扁平标签池体系（日记标签池 + 资产标签池），让各域内需要"分类"的地方快速点选，跨板块统计统一基于标签文本。

**v2 数据归属（重要架构分界）**：
- **账号（本地账号）是新顶层**：PointLog 可有多个本地账号，账号间完全隔离。资产与档案都挂在账号之下。
- **档案（profile）只管"日记类"内容**：打卡、感想、备忘录、主目标、日记标签池——档案在账号内，账号下可有多个档案。
- **资产/收支属于账号级**：每个账号各有一套资产（账户/收支/资产标签池），**切换档案不影响**，切换账号则整套换。
- **标签池分两套**：日记标签池（档案级，随档案走）与资产标签池（账号级，随账号走），各自独立——"账归账、点归点"。

**v2 页面结构**（vue-router 多页面）：
- **账号页**：账号选择/登录/新建/注销/自动登录设置（新顶层入口）
- **主页面（日记）**：v1 内容，受"当前账号 + 当前档案"隔离
- **资产页**：当前账号的账户余额总览、记收支/转账
- **资产统计页**：资产多维筛选分析（账户/标签/收支/日期 + 粒度可调）；折线看收支趋势、饼图看标签占比
- **统计页**：跨板块统计（日记 + 资产维度）
- **设置页**：标签池管理、账户/资产账户管理、当前账号的档案管理、账号 PIN 管理

**v2 分期**（每期独立可验收）：
- **v2.0 地基**：设置页 + 标签池（含 v1 打卡类别改为选标签的改造）
- **v2.1 资产**：账户 + 余额快照 + 收支/转账流水（随性记账，账号级）
- **v2.2 统计**：统计仪表盘（分 3 个子迭代推进）
- **v2.3 本地账号系统**：账号层（档案与资产挂到账号下）+ 账号锁（唯一总锁，10分钟免输）+ 账号页（本次新增）
- **v2.4 打卡体验**：时间改为可选时段（自动算消耗时长）+ 点数支持 0（只记录）+ 打卡记录区间导出 + 历史记录迁移为"不选时间"

## 1. 设计原则（延续 v1，v2 追加）

1. 极轻量：记录成本必须低到"随手"，任何让记录变重的功能都该砍掉。
2. 高度自由：标签、标准、分类均由用户自定义，不预置强制列表。
3. 本地优先 + 私密：数据在本地文件；**统计洞察不做大模型总结**（数据不出本机、且个人自有判断）。
4. **余额为真值、流水作解释**：资产功能里账户余额是最可信的，收支流水只是解释余额变化；允许对不上账。
5. **日记与资产分域**：档案隔离日记类内容；资产为个人级全局共享，两者不混。

## 2. v2.0 标签池（地基）

### 2.1 概念
- **两套标签池，各自独立**：
  - **日记标签池**（档案级）：跟随当前档案，用于打卡"类别"等日记类内容；
  - **资产标签池**（个人级）：全局一套，用于收支、平台等资产类内容。
- 每套池都是**扁平标签**（如：学习、运动 / 饮食、买菜、微信…），一个标签就是一个词，**不支持父子层级**。
- 所有需要"分类"的地方从**对应域的池中**快速点选，而非每次手打。
- v1 打卡的"类别"字段升级为"从日记标签池选择（可选标签/新增标签）"。
- **关键设计：记录里存的是"标签文本"而非标签 ID**。标签池只是"快捷填写词库"：
  - 提交打卡/收支时，实际写入的是所选标签的文本（可再编辑）；
  - 因此删除池中某个标签，**不影响任何历史记录**（历史里仍保留当时的文本），标签池可随时增删、纯属快捷工具。

### 2.2 功能需求
- **设置页（新页面）**：
  - 日记标签池管理（档案级：随档案切换显示对应档案的词库）
  - 资产标签池管理（个人级：全局一套）
  - 查看/新增/删除标签（删除仅影响池本身，历史记录保留文本，无需额外处理）
  - （v2.1 后）账户管理也在此页
- **打卡表单改造**：类别输入从自由文本改为"标签选择器"（点选当前档案日记标签池，或快速新增进池）。

## 3. v2.1 资产（随性记账）

### 3.1 概念（用户核心设计）
```
账户 = 独立记账的"平台/钱包"（现金 / 银行卡A / 微信 / 支付宝 / QQ钱包…）
   ├─ 各账户互相独立记账、互不互通（各自流水与余额）
   ├─ 另有"总览"= 把各账户余额汇总成个人总资产
   ├─ 资产数据为【个人级/全局共享】：不受档案切换影响，全应用只有一套
   ├─ 账户余额是唯一可信的"真值"
   │    ├─ 随时手动更新余额（看真实 App 后校准，重置基准，不理会与流水的差值）
   │    └─ 记收支 / 转账 → 自动按金额更新相关账户余额
```
- 忘了记某笔也没关系：直接手动更新余额即可回到真实，无需补那笔账。
- 记账可指定"某时刻"（像打卡可改时间），用于补录历史（补账）。
- **货币**：全部换算为人民币，允许小数（两位）。
- 负债账户（如欠款）以**负数记余额**（kind=负债），总资产 = Σ 资产账户余额 + Σ 负债账户余额（负债自然为负）。

### 3.2 数据模型（草案）
- `account`：{ id, name, balance, kind: 资产|负债 }
- 收支流水 `tx`：{ id, type: expense|income, account_id, amount(正数), tags[](文本), content, note, ts }
  - **content/note**：收支记录有"内容"与"备注"（不强制，但都可写）
- **转账** `tx`（type=transfer）：{ id, type: transfer, from_account, to_account, amount, note, ts }
  - 转账 = **一条记录**（不是两条收支），同时更新两个账户余额；
  - 统计消费/收入时按 type 排除 transfer（转账只是换口袋，不构成收支）；
  - 转账同样可带 note 备注。
- 余额快照（手动更新时留痕）：{ account_id, balance, ts, note? }
- 账户的"平台"身份 = 账户本身（微信钱包就是一个账户），无需再贴平台标签。

### 3.3 功能需求
- 账户 CRUD（设置页或资产页）：新增账户（现金/卡/钱包…）、可设 kind（资产/负债，负债余额用负数）
- 记一笔收支：选账户 → 类型（收入/支出）→ 金额 → 打标签 → 内容 + 备注 → 提交（自动同步余额）
- **转账**：选"从 A 到 B + 金额 + 备注"→ 一条记录，两端余额自动同步
- 手动更新某账户余额（重置基准）
- 补账：为某账户补某时刻的收支/余额/转账
- **导出 JSON**：可指定日期区间（从几号到几号，含端点；留空＝全部）导出账本
  （账户 / 流水 / 资产标签 / 平账日期），文件中流水按**发生时间升序**（早→晚）排列；
  默认写入项目根 `exports/` 目录（不入版本库），也可选择下载到浏览器
- 资产页总览：各账户当前余额（负债显示为负）、个人总资产、余额分布；可切换查看流水/转账记录

## 4. v2.2 统计仪表盘（新页面，3 子迭代）

> 全程支持**按标签筛选**（基于记录中的标签文本）；时间范围切换（本周/本月/本年/全部）。
> 转账记录（type=transfer）默认不计入收支统计。
> **两个统计域**：日记统计（受当前档案影响：打卡/感想/备忘）与资产统计（个人级：收支/账户），页面内分区或切换维度呈现。

### 4.1 子迭代 1 · 坚持与概况
- 指标卡：累计打卡天数、本月点数、当前连续天数（streak）、最长连续
- streak 可视化（点亮连续天）
- 回答："我到底坚持了多久、有没有断"

### 4.2 子迭代 2 · 结构与规律
- 标签/类别占比（打卡维度）+ 排名
- 星期分布（一周七天，哪天最努力）
- 时段分布（早/午/晚/深夜打卡分布）
- 回答："时间花在哪、我什么时段状态好"

### 4.3 子迭代 3 · 趋势与洞察
- 月度点数趋势曲线（可叠加 v1 点数线基准）
- 感想记录率（写了感想的天占比）
- 收支趋势可并入（资产与打卡统一看"这周的花销 vs 努力"）

- 前端：Vite + Vue 3 SFC（已迁）；引入 **vue-router** 做多页面导航（日记 / 统计 / 设置 / 资产），页面即路由视图。
- 图表：采用现成库（计划 **ECharts**，构建时按需引入），不自绘。
- 后端：继续 Blueprint 分层；新增 stats / assets / tags 等模块（拆分与测试延续 v1 习惯）。
- **数据存储规划（重要）**：v1 所有数据存于 `data/<档案>/data.json`。v2 引入"个人级"数据后需分层：
  - 日记类（档案级）→ 沿用 `data/<档案>/data.json`
  - 资产类 + 资产标签池（个人级/全局）→ 需独立存储，不受档案目录影响（如 `data/global.json` 或 `data/personal/`），并确保切档案/多档案共用；该目录结构在 v2.0 落地时确定。

## 6. 非目标（v2 不做）

- 不做预算、账单分期、复利等专业记账功能（打不过专业软件，且违背轻量）
- 不做标签层级/父子结构

## 9. v2.3 本地账号系统

### 9.1 概念
账号（本地账号）是新顶层：可多开（如"我的账号/家人账号"），账号间**完全隔离**。
- 档案（日记）在账号内，账号下可有多个档案
- 资产（账户/收支/资产标签池）随账号走
- 目前仅本地实现，无联网账号

### 9.2 使用流程
```
启动
 ├─ 未开启自动登录 → 账号选择页（列本地账号 / ＋新建账号）
 │    选账号 → 该账号有账号 PIN 且不在 10 分钟免输窗口 → 输账号 PIN → 进入
 ├─ 开启自动登录 → 直接进入上次账号（同样受 10 分钟免输窗口约束）
      ↓
  账号主页：日记 / 资产 / 统计 / 设置 + 该账号下档案列表
      ↓ 选档案
  档案日记视图（档案本身不再有独立锁）
```

### 9.3 账号锁 + 10 分钟免输（v2.3 定稿）
- **账号锁是唯一的总锁**：每个账号可设一个账号 PIN（哈希存账号 settings）。设锁账号在"进入账号"时需输 PIN。
- **档案锁取消**：v1 档案级 PIN 不再启用（旧数据里若存在也不提示、不删除，仅忽略）。账号锁已能保护账号内全部档案，档案锁冗余。
- **10 分钟免输窗口**：账号解锁成功后在**内存**记录 `unlocked_until = now + 10 分钟`；窗口内再次进入该账号（含刷新页面、切换账号后再回）**免输账号 PIN**。
- 窗口存于**内存（服务进程生命周期）**：服务重启（关掉再双击打开）即失效，需重新输 PIN——符合"防外人趁你不在翻看"的定位。
- **手动锁定**：设 PIN 账号可从顶栏 / 设置页点「锁定」立即锁定——结束会话并**清空免输窗口**，回到"已锁定，输入账号 PIN 解锁"界面；解锁即重新登录。
- **闲置自动锁定**：设 PIN 账号**连续无操作 10 分钟**自动锁定（与手动锁定同语义；任何操作都会刷新计时）。

### 9.4 账号操作
- **新建账号**：建全新账号（内部为空，自动含一个默认档案），可设账号 PIN。
- **登出**：退出当前账号 → 回账号选择页。
- **改账号名**：账号可改名（目录/档案/资产随之迁移；设了 PIN 需验证）。同名或非法名被拒。
- **注销账号**：删除该账号及其全部档案、资产（若该账号设了 PIN 需输 PIN + 防误触验证码）。
- **自动登录开关**（设置页账号区）：
  - 开启：下次启动直接进入上次账号（该账号有 PIN 且超窗口则输 PIN）。
  - 关闭：每次启动都到账号选择页。
  - **登出后停留在账号选择页**（可切换/新建账号），本进程内不再自动登录；服务重启后恢复自动登录。

### 9.5 数据布局（草案）
```
data/
├─ accounts.json            # 账号元数据：列表、当前账号、自动登录标记
└─ <账号>/
   ├─ settings.json         # 该账号账号 PIN 哈希等
   ├─ assets.json           # 该账号资产（承接原 global.json：accounts/txs/asset_tags）
   └─ <档案>/data.json      # 该账号下档案的日记数据（原 data/<档案> 结构下移一层）
迁移：旧 data/<档案>/* 与 data/global.json → 并入首个账号（如"我的账号"），首启自动执行
```

### 9.6 需要兼容/改造的既有能力
- v1 档案切换 → 账号内档案管理；**档案 PIN 移除/忽略**
- v2.1 资产从全局 `data/global.json` → 改挂账号下
- 打卡/感想/备忘/统计读取"当前账号 + 当前档案"
- 顶层锁语义从"档案"迁移到"账号"，10 分钟免输在服务进程内存内有效

### 9.7 验收要点（草案）
- [ ] 可新建多个本地账号，账号间日记与资产完全隔离
- [ ] 账号可设/清除账号 PIN；设锁账号需输 PIN 进入
- [ ] 解锁账号后 10 分钟内（服务进程内）进入免输账号 PIN；服务重启后需重输
- [ ] 手动锁定 / 闲置 10 分钟无操作自动锁定：锁定立即结束会话并清免输窗口，须输账号 PIN 解锁
- [ ] 档案切换不再要求档案 PIN（档案锁已取消）
- [ ] 可登出（回账号选择页）与注销（删整个账号，需确认）
- [ ] 自动登录开关：开启直接进上次账号；关闭每次到选择页
- [ ] 旧 v1/v2 数据迁移到默认账号后不丢失（有测试兜底）

## 10. v2.4 打卡体验优化（时间可选 · 时长 · 0 点 · 导出）

### 10.1 时间改为"可选时段"
- 打卡时间**可选、默认不选**：不填＝只记录内容与点数（记录行显示记录时刻，作为"本条未选时间"的参照）；
- 填了就是**时长机制**：填写"开始 → 结束"，提交后记录行自动显示**消耗时长**（如 `1 小时 30 分`），
  卡片标题显示当日已记录时长合计；
- 起止两端**要么都填、要么都留空**（只填一端前后端都拒绝；**结束不能早于开始**，同一时刻＝合法 **0 时长**）；
- **归属时刻（`ts`）可手填、留空则自动**：填了时段 → 取时段开始；否则 → 现在 / 查看历史某天＝当天 12:00。
  按**凌晨 4 点规则**决定记到哪一天（界面新增"归属时刻"输入框，方便把记录调整归属日、或编辑时改时间）。

**快捷记录（v2.4 追加，减少手输时间）**
- 「⏱ 现在结束」：一键把"结束"设为此刻；开始未填（或晚于此刻）时自动按 30 分钟回推，避免出现空开始；
- 「填用时」：15 / 30 / 45 / 60 / 90 / 120 分钟一键按钮，或自定义分钟数 → 用"结束（缺省＝现在）− 用时"
  自动填入**开始时间**；
- **时长锁定**：填了用时就锁定时长，之后**自行修改结束时间**会自动同步开始时间（时长恒定，跨天也正确）；
  修改开始时间则按新差值更新锁定时长；点「🔗 已锁定时长 · 解除」后开始 / 结束各自独立编辑
  （点「清空」同样解除）；
- 「📍 只记此刻」：起止都设为此刻 → **0 时长**，只记时间点、不计时长；
- 时段行下方**实时显示**"本时段用时 xx"（0 时长显示"只记时间点"），提交前即可确认。

**🌙 记睡眠（v2.4 追加）**
- 打卡表单新增"记睡眠"快捷行：入睡 / 起床（时:分）+ 归属基准（昨晚 / 今天）+「记一条」；
- **起床早于入睡时自动跨到次日**（夜间睡眠天然跨天，如 23:00 → 次日 07:00），归属＝入睡时刻
  （凌晨 4 点规则下整段睡眠归属入睡日）；同一时刻＝ 0 时长；
- 生成一条**类别＝"睡眠"、点数＝0**、填了时段的打卡记录，可随意编辑；
- 一天可多条（午睡 / 夜觉 / 短睡），记录行时段显示 `23:00–次日 07:00`，便于后续统计睡眠规律；
- 若标签池没有"睡眠"会自动加入。

### 10.2 点数支持 0
- 点数允许 **0**（0 点＝单纯记录、不做激励）；
- 0 点记录**不算"打卡日"**：不计入打卡天数、连续天数、点数线与贡献日历（当天级别仍为 0），
  但内容仍保留在当天记录里。

### 10.3 打卡记录导出
- 新增 `GET /api/entries/export`，参数与资产导出一致：
  - `from` / `to`：归属日期区间（含首尾，按凌晨 4 点归属日；留空＝不限）；
  - `download=1`：下载到浏览器；默认落盘项目根 `exports/`（不入版本库）并返回落盘信息
    （`filename` / `rel_path` / `entry_count` / `day_count` / `total_points` / `total_duration_min` …）。
- 导出结构：`{ meta, entries }`；`entries` 按**归属日 + 时间升序**（早 → 晚），每条含
  `day` / `ts` / `start_ts` / `end_ts` / `duration_min` / `points` / `content` / `category`。
- 前端：日记视图新增「⬇️ 导出打卡记录」卡片（区间快捷按钮：近 7 天 / 近 30 天 / 本月 / 全部）。

### 10.4 历史数据迁移（不选时间）
- 旧记录的时间是"记录时刻"（多为提交时的默认值），新机制下统一视为**未选时间**；
- `python migrate_entries.py`（幂等，支持 `--dry-run`）：把旧记录 `ts` 规范化为**归属日 12:00（本地）**，
  `start_ts` / `end_ts` 置 `null`；**归属日与点数不变**；改写前自动留 `data.json.bak` 备份。
