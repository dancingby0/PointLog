# PointLog 需求说明 v2

> 状态：需求确定中（v2 范围）
> v1 已完工并验收（见 `requirements-v1.md`）。本文档在 v1 基础上规划 v2，随开发持续演进。

## 0. v2 背景与目标

**v1 解决**：把每天的投入量化成点数，找回"今天没白过"的正反馈（打卡/感想/备忘录/主目标/点数线/贡献日历/多档案+PIN/导出）。

**v2 想补的两块拼图**：
1. **"看懂自己"**——除了每天记，还要能回顾：我坚持了多久、时间花在哪、在进步还是滑坡（统计仪表盘）。
2. **"看懂钱"**——轻量地知道自己的资产状况，且不违背 PointLog"随性、极轻、私密"的基因（资产 + 随性记账）。

**地基**：扁平标签池体系（日记标签池 + 资产标签池），让各域内需要"分类"的地方快速点选，跨板块统计统一基于标签文本。

**v2 数据归属（重要架构分界）**：
- **档案（profile）只管"日记类"内容**：打卡、感想、备忘录、主目标——它们延续 v1 按档案隔离。
- **资产/收支属于"个人级"（全局共享）**：账户、流水、余额、总资产只有一套，**不受当前档案影响**——切到哪个档案看，钱都是同一套。
- **标签池分两套**：日记标签池（档案级，随档案走）与资产标签池（个人级，全局一套），各自独立、互不混用——"账归账、点归点"，且归属天然对应其数据域。

**v2 页面结构**（vue-router 多页面）：
- **主页面（日记）**：v1 全部内容，受档案隔离
- **资产页**：账户余额总览、记收支/转账（个人级，全局共享）
- **统计页**：跨板块统计（日记 + 资产维度）
- **设置页**：标签池管理、账户管理、（档案/PIN 管理等收纳于此）

**v2 分期**（每期独立可验收）：
- **v2.0 地基**：设置页 + 标签池（含 v1 打卡类别改为选标签的改造）
- **v2.1 资产**：账户 + 余额快照 + 收支/转账流水（随性记账，个人级）
- **v2.2 统计**：统计仪表盘（分 3 个子迭代推进）

## 1. 设计原则（延续 v1，v2 追加）

1. 极轻量：记录成本必须低到"随手"，任何让记录变重的功能都该砍掉。
2. 高度自由：标签、标准、分类均由用户自定义，不预置强制列表。
3. 本地优先 + 私密：数据在本地文件；**统计洞察不做大模型总结**（数据不出本机、且个人自有判断）。
4. **余额为真值、流水作解释**：资产功能里账户余额是最可信的，收支流水只是解释余额变化；允许对不上账。
5. **日记与资产分域**：档案隔离日记类内容；资产为个人级全局共享，两者不混。

## 2. v2.0 标签池（地基）

### 2.1 概念
- **两套标签池，各自独立**：
  - **日记标签池**（档案级）：跟随当前档案，用于打卡"类别"等日记类内容；
  - **资产标签池**（个人级）：全局一套，用于收支、平台等资产类内容。
- 每套池都是**扁平标签**（如：学习、运动 / 饮食、买菜、微信…），一个标签就是一个词，**不支持父子层级**。
- 所有需要"分类"的地方从**对应域的池中**快速点选，而非每次手打。
- v1 打卡的"类别"字段升级为"从日记标签池选择（可选标签/新增标签）"。
- **关键设计：记录里存的是"标签文本"而非标签 ID**。标签池只是"快捷填写词库"：
  - 提交打卡/收支时，实际写入的是所选标签的文本（可再编辑）；
  - 因此删除池中某个标签，**不影响任何历史记录**（历史里仍保留当时的文本），标签池可随时增删、纯属快捷工具。

### 2.2 功能需求
- **设置页（新页面）**：
  - 日记标签池管理（档案级：随档案切换显示对应档案的词库）
  - 资产标签池管理（个人级：全局一套）
  - 查看/新增/删除标签（删除仅影响池本身，历史记录保留文本，无需额外处理）
  - （v2.1 后）账户管理也在此页
- **打卡表单改造**：类别输入从自由文本改为"标签选择器"（点选当前档案日记标签池，或快速新增进池）。

## 3. v2.1 资产（随性记账）

### 3.1 概念（用户核心设计）
```
账户 = 独立记账的"平台/钱包"（现金 / 银行卡A / 微信 / 支付宝 / QQ钱包…）
   ├─ 各账户互相独立记账、互不互通（各自流水与余额）
   ├─ 另有"总览"= 把各账户余额汇总成个人总资产
   ├─ 资产数据为【个人级/全局共享】：不受档案切换影响，全应用只有一套
   ├─ 账户余额是唯一可信的"真值"
   │    ├─ 随时手动更新余额（看真实 App 后校准，重置基准，不理会与流水的差值）
   │    └─ 记收支 / 转账 → 自动按金额更新相关账户余额
```
- 忘了记某笔也没关系：直接手动更新余额即可回到真实，无需补那笔账。
- 记账可指定"某时刻"（像打卡可改时间），用于补录历史（补账）。
- **货币**：全部换算为人民币，允许小数（两位）。
- 负债账户（如欠款）以**负数记余额**（kind=负债），总资产 = Σ 资产账户余额 + Σ 负债账户余额（负债自然为负）。

### 3.2 数据模型（草案）
- `account`：{ id, name, balance, kind: 资产|负债 }
- 收支流水 `tx`：{ id, type: expense|income, account_id, amount(正数), tags[](文本), content, note, ts }
  - **content/note**：收支记录有"内容"与"备注"（不强制，但都可写）
- **转账** `tx`（type=transfer）：{ id, type: transfer, from_account, to_account, amount, note, ts }
  - 转账 = **一条记录**（不是两条收支），同时更新两个账户余额；
  - 统计消费/收入时按 type 排除 transfer（转账只是换口袋，不构成收支）；
  - 转账同样可带 note 备注。
- 余额快照（手动更新时留痕）：{ account_id, balance, ts, note? }
- 账户的"平台"身份 = 账户本身（微信钱包就是一个账户），无需再贴平台标签。

### 3.3 功能需求
- 账户 CRUD（设置页或资产页）：新增账户（现金/卡/钱包…）、可设 kind（资产/负债，负债余额用负数）
- 记一笔收支：选账户 → 类型（收入/支出）→ 金额 → 打标签 → 内容 + 备注 → 提交（自动同步余额）
- **转账**：选"从 A 到 B + 金额 + 备注"→ 一条记录，两端余额自动同步
- 手动更新某账户余额（重置基准）
- 补账：为某账户补某时刻的收支/余额/转账
- 资产页总览：各账户当前余额（负债显示为负）、个人总资产、余额分布；可切换查看流水/转账记录

## 4. v2.2 统计仪表盘（新页面，3 子迭代）

> 全程支持**按标签筛选**（基于记录中的标签文本）；时间范围切换（本周/本月/本年/全部）。
> 转账记录（type=transfer）默认不计入收支统计。
> **两个统计域**：日记统计（受当前档案影响：打卡/感想/备忘）与资产统计（个人级：收支/账户），页面内分区或切换维度呈现。

### 4.1 子迭代 1 · 坚持与概况
- 指标卡：累计打卡天数、本月点数、当前连续天数（streak）、最长连续
- streak 可视化（点亮连续天）
- 回答："我到底坚持了多久、有没有断"

### 4.2 子迭代 2 · 结构与规律
- 标签/类别占比（打卡维度）+ 排名
- 星期分布（一周七天，哪天最努力）
- 时段分布（早/午/晚/深夜打卡分布）
- 回答："时间花在哪、我什么时段状态好"

### 4.3 子迭代 3 · 趋势与洞察
- 月度点数趋势曲线（可叠加 v1 点数线基准）
- 感想记录率（写了感想的天占比）
- 收支趋势可并入（资产与打卡统一看"这周的花销 vs 努力"）

## 5. 技术形态（延续 + 新增）

- 前端：Vite + Vue 3 SFC（已迁）；引入 **vue-router** 做多页面导航（日记 / 统计 / 设置 / 资产），页面即路由视图。
- 图表：采用现成库（计划 **ECharts**，构建时按需引入），不自绘。
- 后端：继续 Blueprint 分层；新增 stats / assets / tags 等模块（拆分与测试延续 v1 习惯）。
- **数据存储规划（重要）**：v1 所有数据存于 `data/<档案>/data.json`。v2 引入"个人级"数据后需分层：
  - 日记类（档案级）→ 沿用 `data/<档案>/data.json`
  - 资产类 + 资产标签池（个人级/全局）→ 需独立存储，不受档案目录影响（如 `data/global.json` 或 `data/personal/`），并确保切档案/多档案共用；该目录结构在 v2.0 落地时确定。

## 6. 非目标（v2 不做）

- 不做 AI/大模型自动总结洞察文本
- 不做与真实银行/支付平台的自动对账或导入
- 不做预算、账单分期、复利等专业记账功能（打不过专业软件，且违背轻量）
- 不做标签层级/父子结构
- 多端同步 / 联网账号（延续 v1）
