# PointLog 需求说明 v2

> 状态：需求确定中（v2 范围）
> v1 已完工并验收（见 `requirements-v1.md`）。本文档在 v1 基础上规划 v2，随开发持续演进。

## 0. v2 背景与目标

**v1 解决**：把每天的投入量化成点数，找回"今天没白过"的正反馈（打卡/感想/备忘录/主目标/点数线/贡献日历/多档案+PIN/导出）。

**v2 想补的两块拼图**：
1. **"看懂自己"**——除了每天记，还要能回顾：我坚持了多久、时间花在哪、在进步还是滑坡（统计仪表盘）。
2. **"看懂钱"**——轻量地知道自己的资产状况，且不违背 PointLog"随性、极轻、私密"的基因（资产 + 随性记账）。

**共同地基**：一套**扁平标签池**，让打卡、收支、平台等所有需要"分类"的地方共用，跨板块统计才可能统一。

**v2 分期**（每期独立可验收）：
- **v2.0 地基**：设置页 + 标签池（含 v1 打卡类别改为选标签的改造）
- **v2.1 资产**：账户 + 余额快照 + 收支流水（随性记账）
- **v2.2 统计**：统计仪表盘（分 3 个子迭代推进）

## 1. 设计原则（延续 v1，v2 追加）

1. 极轻量：记录成本必须低到"随手"，任何让记录变重的功能都该砍掉。
2. 高度自由：标签、标准、分类均由用户自定义，不预置强制列表。
3. 本地优先 + 私密：数据在本地文件；**统计洞察不做大模型总结**（数据不出本机、且个人自有判断）。
4. **余额为真值、流水作解释**：资产功能里账户余额是最可信的，收支流水只是解释余额变化；允许对不上账。

## 2. v2.0 标签池（地基）

### 2.1 概念
- 一个档案拥有**一个扁平标签池**（如：学习、运动、饮食、微信、支付宝、买菜…），一个标签就是一个词，**不支持父子层级**。
- 所有需要"分类"的地方从池中**快速点选**，而非每次手打。
- v1 打卡的"类别"字段升级为"从标签池选择（可选标签/新增标签）"。

### 2.2 功能需求
- **设置页（新页面）**：
  - 查看/新增/删除标签（删除需确认；若标签已被历史记录引用，给出提示与处理策略——见待定）
  - （v2.1 后）账户管理也在此页
- **打卡表单改造**：类别输入从自由文本改为"标签选择器"（可点选池中已有标签，或快速新增进池）。

## 3. v2.1 资产（随性记账）

### 3.1 概念（用户核心设计）
```
账户（现金 / 银行卡A / 微信 / 支付宝…）——余额是唯一可信的"真值"
   ├─ 随时手动更新余额（看真实 App 后校准，重置基准，不理会与流水的差值）
   └─ 每次记收支 → 同一次提交做两件事：加一条流水 + 按金额更新该账户余额
```
- 忘了记某笔也没关系：直接手动更新余额即可回到真实，无需补那笔账。
- 记账可指定"某时刻"（像打卡可改时间），用于补录历史（补账）。

### 3.2 数据模型（草案）
- `account`：{ id, name, balance, kind: 资产/负债 }
- 收支流水 `tx`：{ id, account_id, amount(+/−), tags[], content, ts }
- 余额快照（手动更新时留痕）：{ account_id, balance, ts, note? }
- 账户也支持贴标签/平台标记（如"微信"），具体是否独立字段待定。

### 3.3 功能需求
- 账户 CRUD（设置页）
- 记一笔收支：选账户 → 金额（区分收入/支出）→ 打标签 → 提交（自动同步余额）
- 手动更新某账户余额（重置基准）
- 补账：为某账户补某时刻的收支/余额
- 首页展示：各账户当前余额、总资产（资产−负债）概览

## 4. v2.2 统计仪表盘（新页面，3 子迭代）

> 全程支持**按标签/类别筛选**；时间范围切换（本周/本月/本年/全部）。

### 4.1 子迭代 1 · 坚持与概况
- 指标卡：累计打卡天数、本月点数、当前连续天数（streak）、最长连续
- streak 可视化（点亮连续天）
- 回答："我到底坚持了多久、有没有断"

### 4.2 子迭代 2 · 结构与规律
- 标签/类别占比（打卡维度）+ 排名
- 星期分布（一周七天，哪天最努力）
- 时段分布（早/午/晚/深夜打卡分布）
- 回答："时间花在哪、我什么时段状态好"

### 4.3 子迭代 3 · 趋势与洞察
- 月度点数趋势曲线（可叠加 v1 点数线基准）
- 感想记录率（写了感想的天占比）
- 收支趋势可并入（资产与打卡统一看"这周的花销 vs 努力"）

## 5. 技术形态（延续 + 新增）

- 前端：Vite + Vue 3 SFC（已迁）；页面从"单页下滑"变为**多视图/导航**（日记 ←→ 统计 ←→ 设置）。
  - 简单两三个页面：优先考虑轻量 v-show/组件切换，暂不引入 vue-router（待评估）。
- 图表：待决策（自绘 SVG/CSS vs 引入 ECharts）。
- 后端：继续 Blueprint 分层；新增 stats / assets / tags 等模块（拆分与测试延续 v1 习惯）。

## 6. 非目标（v2 不做）

- 不做 AI/大模型自动总结洞察文本
- 不做与真实银行/支付平台的自动对账或导入
- 不做预算、账单分期、复利等专业记账功能（打不过专业软件，且违背轻量）
- 不做标签层级/父子结构
- 多端同步 / 联网账号（延续 v1）

## 7. 验收要点（草案，随迭代细化）

- [ ] 打卡类别可从标签池点选，也可快速新增标签
- [ ] 设置页可管理标签（增删有确认）
- [ ] 记收支后，该账户余额正确同步
- [ ] 手动更新余额后，作为新基准生效（与历史流水对不上也不报错/不补差）
- [ ] 可为历史日期补录收支/余额
- [ ] 统计页可切换时间范围并按标签筛选
- [ ] 三项核心指标与图表数据与真实记录一致（有测试兜底）

- 收支金额精度与币种（仅人民币整数？允许小数？）
- 账户 kind=负债（如欠款）如何展示与合计

- 图表方案：自绘 vs ECharts
- 统计"类别筛选"与标签池的关系细节
- 技术：是否需要 vue-router，还是组件内切换即可
