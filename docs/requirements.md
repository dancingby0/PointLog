# PointLog 需求说明

> 状态：需求确定中（v1 范围）
> 本文档随开发持续演进；更早的原始口语化草稿保留在 git 历史中，可随时回溯核对有没有遗漏想法。

## 1. 背景与目标

**痛点**：不清楚自己每天到底做了什么、投入了多少；努力了却感觉不到进度，缺乏正反馈，容易产生"又荒废了一天"的焦虑。

**目标**：提供一个极轻量的本地记录工具，把每天零散但真实的投入（背课文、做题、运动、散步……）量化成一条条看得见的记录与点数，建立正反馈；同时兼有日记（每日感想）与备忘录的功能。

**定位**：个人私密工具，性质类似私人日记，数据只属于自己。单机本地使用，不依赖网络与云端账号。

## 2. 设计原则

1. **极轻量**：核心场景是"想起来就立刻写下并提交"。任何功能若增加记录负担，都应砍掉或延后。
2. **高度自由**：点数完全由用户按自己的标准赋予，不存在统一标准；类别也由用户自定义。
3. **本地优先**：数据存在本地文件里，不依赖浏览器缓存。
4. **私密**：他人不应能随意翻阅内容。

## 3. 核心使用流程（场景）

- **场景 A（随手记）**：完成一件事（背完一篇课文、跑完步、做出一道算法题）后，立刻打开页面，写下内容、给点数、提交，系统记下当前时间。
- **场景 B（睡前回看）**：睡前写/补今天的感想；顺便看一眼今日点数与近期点数线，确认"今天没有白过"。
- **场景 C（备忘）**：想起寝室周几打扫、某个作业 deadline，随手记进备忘录；主目标（如"主攻物理"）固定置顶提醒自己。

## 4. 功能需求

### 4.1 打卡记录

- 一次提交一条记录，字段为：
  - **时间**：默认 = 按下"提交"按钮的时刻；可手动改为任意时间。
  - **点数**：整数，完全由用户按自己标准赋予（例：运动 2 点、背诵课文 1 点、一道算法题 3 点）。无统一标准。
  - **内容**：一句话描述做了什么。
  - **类别**：可选填。自由文本、由用户自定义（如 物理 / 英语 / 运动 / 杂项），不预置强制列表。
- **日期归属规则**：凌晨 4:00 前提交的记录，默认归属到"昨日"（对晚睡党友好）。
- 记录支持**编辑与删除**（记错点数、写错内容都可以改）。

### 4.2 每日感想

- **一天一篇**，不会出现一天多篇。
- 当天感想可随时**往后追加**；历史日期可**补写**。
- "编辑"指：往某天的感想追加内容，或删除当天整篇感想。
- 内容自由：做了什么梦、去了哪里玩、任何奇奇怪怪的事都可以写。

### 4.3 点数线与统计

- 提供一条近期"点数线"作为激励基准，直观展示近期投入水平。
- **点数线算法（v1 定稿）**：
  1. 窗口：最近至多 **60 个自然日**（按凌晨 4 点规则，取窗口内每日点数；0 分天不进样本）
  2. 有效打卡天数 **≤ 10**：直接取这些天点数的 **40% 分位数**
  3. 有效打卡天数 **> 10**：各剔除点数最低 10% 与最高 10% 的天（`⌊N×10%⌋`），对剩余再取 **40% 分位数**（线性插值）
  - 接口返回完整计算过程（窗口天数 / 有效天数 / 剔除数），便于前端展示与校验。
- 支持**导出为 JSON**，便于日后自行做更深入的统计。
- **贡献日历**：GitHub 风格热力图展示近一年每日点数（按点数分 5 档着色），点击格子可跳转到对应日期。
  （分级规则当前为简化分档：0 / 1 / 2-3 / 4-5 / 6+ 点；待有真实数据后可按需调整。）

### 4.4 备忘录

- 常驻的轻量备忘列表，随手记录生活与学习事项（例：寝室周四周五打扫；XX 作业 deadline 是 x 月 x 日）。
- 支持一条**置顶主目标**（例：当前主目标：学习物理），固定在显眼位置。
  - 说明：曾设想的"攻关科目点数加成 / 权重系统"属进阶玩法，放到 v2 讨论；v1 仅做置顶展示。

### 4.5 本地档案与 PIN 锁

- 支持**轻量本地档案（profile）切换**，非联网账号；不同档案之间的所有内容互不共享、完全隔离。
  - 用途 1：区分不同用途 / 账本（如学习一本、生活一本）。
  - 用途 2：防他人直接翻阅私密内容。
- **PIN 锁**：页面闲置超过设定时长后自动锁定，解锁需输入 PIN。
  - 定位：防的是"他人趁用户离开时偷看"，属便捷级防护（防君子不防小人）；文件级加密不在 v1 范围。

## 5. 数据与存储（草案）

- v1 形态为**电脑端浏览器界面**；因浏览器无法直接读写本地文件，将由一个轻量本地程序负责读写数据文件并拉起浏览器页面（具体技术栈待选型确定，详见第 8 节）。
- 数据存放于**本地文件**，不用浏览器缓存 / localStorage 作为唯一存储。
- 存储按档案隔离（如 `data/<档案名>/` 目录结构；具体目录与文件格式在技术方案阶段确定）。
- 每个档案都应能独立导出 JSON。

## 6. 非目标（v1 明确不做）

- 联网账号、注册登录、云端同步、多设备访问
- 照片、视频功能（以后再说）
- 手机端 / 移动端适配（以后再说）
- 攻关科目点数加成 / 权重系统（v2 候选）
- 文件级加密
- 任何社交 / 分享功能
- 预置分类与统一计分标准（违背"自由"原则）

> 维护原则：日后冒出任何新想法，先问自己两句——"它会不会加重记录负担？"、"它是不是 v1 必须？"，再决定进需求还是进"待定"。
